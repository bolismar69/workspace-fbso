# ADR-008: Deploy Docker + Kubernetes — Artefatos de Produção (GAP-010)

**Status:** ✅ Aceito
**Data:** 2026-06-24
**Substitui:** Nenhum
**Substituído por:** Nenhum

---

## Contexto

O microserviço não possuía artefatos de deploy (DT-10). Para homologação em produção, eram necessários:
- Dockerfile multi-stage para build otimizado
- Manifestos Kubernetes (Deployment, Service, ConfigMap, HPA)
- Docker Compose para desenvolvimento local

## Decisão

**Adotar Docker multi-stage build + Kubernetes com HPA para produção. Docker Compose para desenvolvimento local.**

```
deploy/k8s/
├── configmap.yaml    # DATABASE_URL, REDIS_ADDR, RATE_LIMIT_*
├── deployment.yaml   # ms-tax-rates, resource limits, health probes
├── service.yaml      # ClusterIP :3000
└── hpa.yaml          # CPU > 70% → scale 2-10 replicas
```

Dockerfile multi-stage:
```dockerfile
# Stage 1: build (golang:1.25-alpine)
# Stage 2: runtime (alpine:3.20) — binário estático, sem dependências
```

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| **A) Docker + K8s** (escolhida) | Padrão corporativo, escalável | Complexidade inicial |
| B) Binary + systemd | Simples | Sem orquestração, sem health checks automáticos |
| C) Serverless (Lambda) | Zero infra | Cold start inaceitável para cálculo sub-100ms |

## Consequências

- **Positivas:** HPA escala automaticamente. Health probes (`/v1/healthz`, `/v1/health`). Rolling updates sem downtime.
- **Negativas:** Manutenção de manifests K8s. Contexto de build Docker complexo (workspace root).
