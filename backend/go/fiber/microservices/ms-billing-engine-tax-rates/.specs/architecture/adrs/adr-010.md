# ADR-010: Tabela `cst_reforma` como Fonte Oficial de CST para CBS/IBS

**Status:** ✅ Aceito
**Data:** 2026-06-30
**Substitui:** Uso de constantes hardcoded `cstPadrao = "01"` / `cstIsento = "04"` em `internal/reforma/reforma.go`
**Substituído por:** Nenhum
**Feature:** [FEATURE-2026-06-30-DT03-CST-REFORMA-TRIBUTARIA](../../features/FEATURE-2026-06-30-DT03-CST-REFORMA-TRIBUTARIA/)

---

## Contexto

O código atual (`internal/reforma/reforma.go:27-31`) usa 2 constantes hardcoded para CST de CBS/IBS. A LC 214/2025 define **18 CSTs oficiais** com 164 CCTs (Classificações Tributárias) detalhadas, cobrindo cenários como monofásica, diferimento, crédito presumido e alíquotas uniformes setoriais — nenhum modelado pelo código atual. DT-03 captura esta dívida técnica.

Em 2026-06-30, o time de negócio forneceu a tabela oficial da RFB (`CST_cClassTrib_2025-10-03_Public_verde.xlsx`) com 164 registros.

## Decisão

**Criar a tabela `cst_reforma` no PostgreSQL como fonte canônica de CST para CBS/IBS**, populada com os 164 registros oficiais da RFB. Adicionar `GetCSTReforma()` ao `TaxRepository` e refatorar `reforma.go` para consultar o banco em vez de usar constantes.

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| **A) Tabela no PostgreSQL** (escolhida) | Atualizável sem deploy, cacheável via Redis, auditável, consistente com padrão (`iva_dual_rules`) | Requer migration SQL |
| B) Constantes em Go (switch/case) | Sem dependência de DB | 164 cases hardcoded, requer deploy para atualizar |
| C) Arquivo JSON embutido (`embed.FS`) | Sem dependência de DB | Não auditável, requer deploy para atualizar |

## Consequências

- **Positivas:** Time Fiscal pode revisar/atualizar CSTs sem deploy (via Admin Fiscal). Cache Redis automático. Habilita DT-04 (créditos) e split payment (GAP-006).
- **Negativas:** +1 consulta ao banco por cálculo de CBS/IBS (mitigada por cache Redis). 164 INSERTs no `init.sql`.
