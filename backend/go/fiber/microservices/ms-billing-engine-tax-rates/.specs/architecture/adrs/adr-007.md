# ADR-007: API Versioning — Prefixo `/v1/` com Rotas Legacy Deprecadas

**Status:** ✅ Aceito
**Data:** 2026-06-24
**Substitui:** Nenhum
**Substituído por:** Nenhum

---

## Contexto

O endpoint original era `POST /calculate` sem versionamento. A Reforma Tributária (2026–2033) implica mudanças significativas nos schemas de entrada e saída ao longo dos anos (ex: extinção de PIS/COFINS em 2027, split payment em 2029).

Sem versionamento, qualquer breaking change no schema quebraria todos os consumidores simultaneamente.

## Decisão

**Adotar prefixo `/v1/` em todas as rotas.** Rotas legacy (`/calculate`, `/healthz`, `/metrics`) mantidas com header `Deprecation: true` e warning no log.

```go
v1 := app.Group("/v1")
v1.Post("/calculate", calculateHandler)
v1.Get("/healthz", healthzHandler)
// ...
app.Post("/calculate", withDeprecation(calculateHandler)) // legacy
```

Versão `v2` planejada para incorporar split payment e créditos do Lucro Real (BR-08, BR-09).

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| **A) Prefixo `/v1/`** (escolhida) | Padrão REST, evolução não-quebrante | Rotas legacy para manter |
| B) Header `Accept: application/vnd.taxnexus.v1+json` | "REST puro" | Complexo para consumidores, difícil testar com curl |
| C) Query param `?version=1` | Simples | Polui URL, não semântico |

## Consequências

- **Positivas:** `/v2/` pode introduzir breaking changes sem afetar `/v1/`. Consumidores migram no seu ritmo.
- **Negativas:** ~6 rotas legacy para manter com deprecation warning. Duplicação de registros no Fiber.
