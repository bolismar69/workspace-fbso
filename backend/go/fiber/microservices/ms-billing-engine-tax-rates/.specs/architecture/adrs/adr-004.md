# ADR-004: Strategy Pattern para Cálculo de PIS/COFINS por CST

**Status:** ✅ Aceito
**Data:** 2026-06-20
**Substitui:** Nenhum
**Substituído por:** Nenhum

---

## Contexto

PIS e COFINS têm comportamento de cálculo radicalmente diferente dependendo do CST (Código de Situação Tributária):
- CST 01/02: tributação normal (alíquota cheia sobre base)
- CST 03: monofásico (alíquota zero para o contribuinte)
- CST 04: monofásico (alíquota zero)
- CST 06: alíquota zero
- CST 49: suspensão
- CST 50-99: diversas situações (todos retornam valor zero)

Um único método `Calculate()` com switch/case de 15+ branches seria ilegível e difícil de estender.

## Decisão

**Implementar Strategy Pattern com função fábrica por CST.** Cada CST tem sua própria struct strategy que implementa uma interface comum. `GetPISStrategy(cst)` / `GetCOFINSStrategy(cst)` retornam a estratégia correta.

```go
type PISStrategy interface {
    Calculate(base decimal.Decimal, aliquota decimal.Decimal) decimal.Decimal
}
// Exemplos: PIS01_02{}, PIS03{}, PIS04{}, PIS49{}, PIS50To99{}, PIS99{}
```

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| **A) Strategy Pattern** (escolhida) | Extensível, testável por CST, open/closed principle | Mais arquivos |
| B) Switch/case único | Simples | 15+ branches, difícil de testar isoladamente |
| C) Tabela de configuração no banco | Atualizável sem deploy | Overhead de DB para lógica determinística |

## Consequências

- **Positivas:** 100% de cobertura de CSTs (15 estratégias PIS + COFINS). Adicionar novo CST = nova strategy, sem modificar existentes.
- **Negativas:** Duplicação de estrutura entre PIS e COFINS (resolvida com padrão consistente).
