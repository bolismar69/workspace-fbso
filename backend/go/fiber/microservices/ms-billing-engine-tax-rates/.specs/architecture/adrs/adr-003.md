# ADR-003: Cache Redis + Circuit Breaker como Camada de Resiliência Regulatória

**Status:** ✅ Aceito
**Data:** 2026-06-21
**Substitui:** Nenhum
**Substituído por:** Nenhum

---

## Contexto

O cálculo de CBS/IBS depende de consulta à tabela `iva_dual_rules` (PostgreSQL) para cada item do documento fiscal. Sem cache, isso gera N consultas ao banco por requisição. Além disso, a futura API do Comitê Gestor do IBS (LC 214/2025) será uma dependência externa com SLA desconhecido.

O Project Charter (Seção 7) identifica "Indisponibilidade de Alíquotas do IBS por Município" como risco #1.

## Decisão

**Implementar cache Redis (TTL 24h) como camada primária, com fallback PostgreSQL e Circuit Breaker para API externa.**

Estratégia de fallback em 4 níveis:
```
1. Redis (TTL 24h, chave: tax:iva:<ncm>:<uf>:<municipio>)
2. PostgreSQL (tabela iva_dual_rules, índice NCM+UF+IBGE)
3. API Comitê Gestor IBS (via CircuitBreakerIBSClient — planejada, Gap G2)
4. Alíquotas default hardcoded (último recurso, com slog.Warn)
```

**Circuit Breaker (F-007):** 3 falhas em 60s → OPEN, HALF_OPEN após 5min, cache expirado como fallback.

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| **A) Redis + Circuit Breaker** (escolhida) | Resiliência, cache compartilhado, padrão consistente | Complexidade adicional |
| B) Apenas PostgreSQL | Simples | N consultas/request, sem proteção contra API externa |
| C) Cache in-memory (sync.Map) | Sem dependência Redis | Não compartilhado entre instâncias, perdido no restart |

## Consequências

- **Positivas:** Segunda consulta sub-ms (cache hit). Réplica local garante operação contínua sem API externa. Consistente com padrão do projeto (`CachedTaxRepository`).
- **Negativas:** Circuit Breaker para API IBS não testado em produção (API não publicada — Gap G2).
