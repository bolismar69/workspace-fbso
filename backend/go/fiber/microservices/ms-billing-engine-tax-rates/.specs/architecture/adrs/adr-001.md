# ADR-001: Motor de Cálculo Unificado — `BillingEnginePhased` SOP-013 7-fases

**Status:** ✅ Aceito
**Data:** 2026-06-20
**Substitui:** Nenhum
**Substituído por:** Nenhum

---

## Contexto

O cálculo de tributos brasileiros envolve dependências assimétricas entre eles: o IPI compõe a base do ICMS, o ICMS deve ser excluído da base do PIS/COFINS ("Tese do Século", STF), o FUST/FUNTTEL dependem de ICMS+PIS+COFINS já calculados. A ordem de cálculo IMPORTA.

O motor inicial (`BillingEngineOrdered`) tinha apenas 2 fases (IPI sequencial → ICMS+PIS/COFINS+Reforma paralelo), insuficiente para modelar todas as dependências.

## Decisão

**Adotar arquitetura multi-fase genérica com `CalculationPhase` e modos `Sequential`/`Parallel`.**

Pipeline SOP-013 de 7 fases:
```
F0 (Seq) → IS          ← pré-filtro NCM seletivo
F1 (Seq) → IPI         ← compõe base do ICMS
F2 (Seq) → CBS         ← "por fora", não compõe base de outros
F3 (Seq) → ICMS        ← antes do PIS/COFINS (Tese do Século)
F4 (Par) → IBS + ISS + PIS/COFINS  ← com exclusão do ICMS
F5 (Seq) → FUST        ← depende ICMS+PIS+COFINS
F6 (Seq) → FUNTTEL     ← mesma base do FUST
```

`injectTributoValues()` propaga valores calculados entre fases automaticamente.

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|-------------|------|---------|
| **A) Multi-fase genérica** (escolhida) | Extensível, modela dependências reais, testável por fase | Mais complexo que motor simples |
| B) Motor bifásico original | Simples | Não modela dependências assimétricas, ordem fixa |
| C) Execução totalmente paralela | Performance máxima | Resultados incorretos (IPI→ICMS, ICMS→PIS/COFINS) |

## Consequências

- **Positivas:** CBS "por fora" antes do ICMS. ICMS antes do PIS/COFINS. FUST/FUNTTEL em cascata com dependências corretas. Arquitetura extensível para novos tributos.
- **Negativas:** Complexidade de orquestração. Necessidade de `injectTributoValues()` entre fases.
