# Feature: Completar ICMS Próprio + ICMS-ST Regras Gerais

> **Data:** 2026-06-20
> **Arquivo modificado:** `internal/legacy/icms.go`

## Resumo

Reestruturação completa do método `Calculate()` do `ICMSCalculator` para integrar `getEffectiveTaxConfig()` no fluxo principal e implementar regras gerais de ICMS-ST (interno e interestadual) sem depender exclusivamente de exceção de produto.

## Problema Anterior

O fluxo do ICMS estava fragmentado:
1. Se havia exceção de produto → apenas ICMS-ST com MVA da exceção
2. Senão → Simples Nacional OU CST 010 (ST com 18% hardcoded)
3. DIFAL sempre executado ao final

O `getEffectiveTaxConfig()` existia mas **nunca era chamado** no fluxo principal — ele fazia o merge inteligente de regra geral + exceção mas o resultado era descartado.

## Solução Implementada

### Novo fluxo estruturado

```
Calculate()
├── Para cada item:
│   ├── 1. getEffectiveTaxConfig() → merge regra geral + exceção de produto
│   ├── 2. Se Simples Nacional → calcularICMSSimples()
│   └── 3. Senão (Regime Normal):
│       ├── Operação Interna → calcularICMSOperacaoInterna()
│       │   ├── CST 010 ou protocolo ST + MVA? → ICMS_ST
│       │   └── Senão → ICMS (próprio) + FCP
│       └── Operação Interestadual → calcularICMSOperacaoInterestadual()
│           ├── ICMS (interestadual) — sempre calculado
│           ├── Destino final? → + DIFAL (CalcularDIFAL)
│           └── Protocolo ST + MVA? → + ICMS_ST
```

### Novos métodos auxiliares

| Método | Responsabilidade |
|--------|-----------------|
| `calcularICMSSimples()` | Simples Nacional: equivalência CSOSN + alíquota efetiva |
| `calcularICMSOperacaoInterna()` | ICMS próprio interno + ICMS-ST interno |
| `calcularICMSOperacaoInterestadual()` | ICMS interestadual + DIFAL + ICMS-ST interestadual |

### Mudanças específicas

1. **ICMS Próprio interno:**
   - Base de cálculo com redução (`config.ReducaoBase`)
   - Alíquota efetiva via `getEffectiveTaxConfig()` (regra + exceção merge)
   - Cálculo de FCP integrado
   - `MoreNumericDetails` com memória de cálculo completa

2. **ICMS-ST interno (regra geral):**
   - Acionado quando CST=010 OU `config.PossuiProtocoloST && MVA > 0`
   - MVA pode vir do config (regra geral) ou de override no item (CST 010)
   - Sem dependência de `product_tax_exceptions` para ST

3. **ICMS Interestadual:**
   - Sempre calculado (antes era pulado para operações interestaduais)
   - Base com redução quando configurado

4. **ICMS-ST interestadual (regra geral):**
   - Acionado quando `config.PossuiProtocoloST && MVA > 0`
   - MVA via `getEffectiveTaxConfig()` — se a exceção de produto tiver MVA, ela é injetada no config

5. **DIFAL:**
   - Agora recebe `ICMSConfig` em vez de `*ICMSRule`
   - Usa as alíquotas do config efetivo (já mergeado com exceção)

6. **Fallback em caso de erro:**
   - Se `getEffectiveTaxConfig()` falhar, loga warning e pula o item
   - Se `GetSimplesFaixa()` falhar, loga warning e pula Simples
   - ZERO panics — toda falha é degradação graciosa

### Código removido

- Bloco `if err == nil && exception != nil { ... } else { ... }` que bifurcava o fluxo
- Cálculo de ICMS-ST com alíquota 18% hardcoded (linha 118 do original)
- Bloco de pseudocódigo comentado (TODO lines 269-280)
- Lógica DIFAL standalone (integrada no método interestadual)
