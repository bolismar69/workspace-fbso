# ADR-0001: Uso de Chaves Naturais (Código IBGE) como Primary Key

## Contexto

O sistema precisa armazenar a hierarquia geopolítica brasileira (UF → Região Intermediária → Região Imediata → Município → Distrito → Subdistrito) a partir dos dados da Divisão Territorial Brasileira (DTB) do IBGE.

Cada entidade possui um código oficial atribuído pelo IBGE:
- UF: 2 dígitos (ex: `35` para SP)
- Região Intermediária: 4 dígitos (ex: `3501`)
- Região Imediata: 6 dígitos (ex: `350001`)
- Município: 7 dígitos (ex: `3550308`)
- Distrito: 9 dígitos (ex: `355030805`)
- Subdistrito: 11 dígitos (ex: `35503080501`)

A questão era: usar esses códigos como chaves primárias naturais ou adicionar surrogate keys (UUID ou auto-increment)?

## Decisão

**Usar os códigos IBGE como chaves primárias naturais (`String`).**

Todas as entidades têm `@Id` do tipo `String` contendo o código IBGE completo. Nenhuma surrogate key é utilizada.

## Alternativas Consideradas

| Alternativa | Prós | Contras | Motivo da Rejeição |
|---|---|---|---|
| **Surrogate Key (UUID)** | Independência da fonte externa; IDs imutáveis | Complexidade adicional; necessidade de lookup pelo código IBGE; mais espaço em índices | Adiciona complexidade desnecessária — os códigos IBGE já são únicos, estáveis e universais |
| **Surrogate Key (Auto-increment)** | Simples, compacto | Sem significado de negócio; inconsistente entre ambientes; expõe ordem de inserção | IDs com significado facilitam debugging e integração com sistemas externos |
| **Chave Natural (IBGE)** ✅ | Simplicidade; compatibilidade total com sistemas externos; debugging facilitado | Dependente da fonte externa; tamanho variável de chave | Escolhida — os códigos IBGE mudam raramente e apenas em reestruturações territoriais oficiais |

## Consequências

### Positivas
- Integração direta com `ms-geolocalidade` e outros sistemas que usam códigos IBGE
- Debugging facilitado: logs mostram códigos reconhecíveis (ex: `3550308` = São Paulo)
- Sem necessidade de lookup table ou mapeamento adicional
- IDs hierárquicos: o código do subdistrito contém o código do distrito, que contém o do município

### Negativas
- Dependência da estabilidade dos códigos IBGE (mudanças são raras e oficiais)
- Tamanho variável de PK (2 a 11 caracteres) — impacto mínimo em PostgreSQL
- Se o IBGE mudar a estrutura dos códigos, será necessário migration
