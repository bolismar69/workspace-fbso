# ADR-002: NativeWind 4 para Estilização

- **Status:** Aceito
- **Data:** 2025-07-15
- **Stakeholders:** Time de Engenharia

## Contexto

Era necessário definir a estratégia de estilização do app. Opções consideradas:
1. StyleSheet (React Native built-in)
2. Styled Components
3. Tamagui
4. NativeWind (Tailwind CSS para React Native)
5. Restyle (Shopify)

## Decisão

**NativeWind 4 + Tailwind CSS 3.4**, complementado por objetos de tema (`lightTheme`, `darkTheme`) para estilos complexos.

## Justificativa

- **Produtividade**: classes utilitárias familiares para quem conhece Tailwind CSS
- **Consistência**: design tokens centralizados no `tailwind.config.js` (cores primary, secondary, accent, background, neutral)
- **Performance**: NativeWind 4 compila para `StyleSheet.create()` em build time — sem overhead de runtime
- **TypeScript**: classes type-safe com autocomplete
- **Dark Mode**: suporte nativo via `dark:` prefix + tema customizado
- **Cobertura**: temas complementam NativeWind para estilos complexos (cards, sombras, pickers) que exigem objetos de estilo

## Consequências

### Positivas
- Estilização rápida e consistente
- Design tokens centralizados
- Compilação build-time sem custo de runtime
- Familiaridade para devs que conhecem Tailwind

### Negativas
- Configuração adicional de build (Babel plugin)
- Suporte limitado a algumas propriedades CSS específicas do React Native
- Temas complexos ainda exigem StyleSheet objects
- Breaking changes entre versões do NativeWind

## Alternativas Consideradas

| Alternativa | Motivo da Rejeição |
|---|---|
| StyleSheet puro | Verboso, difícil de manter consistência em app grande |
| Styled Components | Overhead de runtime, não recomendado para mobile |
| Tamagui | Curva de aprendizado maior, ecossistema menor |
| Restyle | Muito opinativo, menos flexível que NativeWind |
