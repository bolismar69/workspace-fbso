# ADR-002: Dados Estáticos sem Backend

- **Status:** ✅ Aceito
- **Data:** 2026-07-08
- **Decisão por:** Time de Engenharia

---

## Contexto

O MVP da Solar Fácil precisava de:
- Planos (3 tipos com preços, capacidades, features)
- FAQs (6 perguntas frequentes)
- Lista de concessionárias
- Dados de consumo médio por região
- Calculadora de economia (fórmula fixa: 12% de desconto)

Esses dados mudam com baixa frequência (planos podem mudar trimestralmente, FAQs mensalmente). Não justifica um backend dedicado para o MVP.

## Decisão

**Servir todos os dados de negócio como constantes TypeScript e JSON mocks no bundle client-side, com uma camada de serviços que simula latência de API (500ms delay via `setTimeout`).**

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|---|---|---|
| **API Backend (Go/Java)** | Dados dinâmicos, atualização sem deploy | Overhead de desenvolvimento, deploy, manutenção para MVP |
| **Headless CMS (Strapi/Contentful)** | Painel de edição não-técnico | Custo adicional, dependência externa, latência de rede |
| **Git-based CMS (Tina/Decap)** | Simples, versionado | Complexidade adicional para volume baixo de dados |

## Consequências

### Positivas
- Zero latência de rede para dados (após carregamento inicial)
- Sem custo de infraestrutura backend
- Deploy atômico (dados + código versionados juntos)
- Serviços com delay simulado → migração para API real é mecânica (trocar `setTimeout` por `fetch`)

### Negativas
- Qualquer mudança de dados requer novo deploy
- Bundle JS inclui dados mock (~5KB adicional)
- Sem atualização em tempo real
- Duplicação de dados entre `constants.ts` e `mock*.json`
