# ADR-004: Output Standalone para Hospedagem Não-Vercel

- **Status:** ✅ Aceito
- **Data:** 2026-07-08
- **Decisão por:** Time de Engenharia

---

## Contexto

O Solar Fácil Site precisava ser hospedado em infraestrutura própria (DigitalOcean ou similar), não na Vercel. Isso implica:
- Sem edge functions da Vercel
- Sem ISR via Vercel (Incremental Static Regeneration)
- Sem integração nativa com Vercel Analytics/Logging
- Necessidade de bundle Node.js autossuficiente

## Decisão

**Usar `output: 'standalone'` em `next.config.ts` para gerar um bundle Node.js autossuficiente que pode ser deployado em qualquer servidor com Node.js 20+.**

## Alternativas Consideradas

| Alternativa | Prós | Contras |
|---|---|---|
| **Vercel** | Integração nativa, preview URLs, analytics | Vendor lock-in, custo, decisão de negócio por infra própria |
| **Docker (custom)** | Portabilidade total | Complexidade de configuração, manutenção do Dockerfile |
| **Static Export** | Servível de qualquer CDN | Sem SSR, sem API Routes, sem server components |

## Detalhes da Implementação

```typescript
// next.config.ts
const nextConfig: NextConfig = {
  output: 'standalone',
  // ...
};
```

O build produz `.next/standalone/` contendo:
- `server.js` — entry point Node.js
- `.next/` — build artifacts
- `node_modules/` — dependências necessárias

## Consequências

### Positivas
- Deploy em qualquer servidor Node.js (DigitalOcean, AWS EC2, etc.)
- Sem vendor lock-in
- Bundle autossuficiente (não precisa de `npm install` no servidor)
- CI/CD simples: `next build` → copiar `.next/standalone/` → `node server.js`

### Negativas
- Sem preview URLs automáticas
- Sem ISR (Incremental Static Regeneration)
- Sem analytics de plataforma (depende de GA4 client-side)
- Responsabilidade de gerenciar o servidor Node.js (monitoring, restart, scaling)
