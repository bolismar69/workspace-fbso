# ADR-001: Escolha de Next.js 16 App Router + React 19

- **Status:** ✅ Aceito
- **Data:** 2026-07-08
- **Decisão por:** Time de Engenharia

---

## Contexto

O projeto Solar Fácil Site precisava de um framework frontend com:
- SEO robusto (página pública, precisa rankear no Google)
- Performance (LCP baixo, principalmente mobile — persona principal acessa via celular)
- Separação clara entre conteúdo estático (seções institucionais) e interativo (calculadoras, formulários)
- Facilidade de deploy em hospedagem não-Vercel (DigitalOcean ou similar)

## Decisão

**Usar Next.js 16.2.10 com App Router + React 19.2.4.**

## Alternativas Consideradas

| Alternativa | Prós | Contras | Por que rejeitada |
|---|---|---|---|
| **Vite + React SPA** | Simples, rápido, bundle menor | Sem SSR → SEO ruim, sem server components | Página pública precisa de SSR para SEO |
| **Next.js 14 Pages Router** | Conhecido, estável | Legacy — sem Server Components, sem streaming SSR | App Router é o futuro do Next.js |
| **Remix** | Bom para formulários, nested routes | Ecossistema menor, menos documentação em pt-BR | Time já conhece Next.js |
| **Astro** | Excelente para conteúdo estático | Interatividade limitada para SPA-like components | Calculadoras e formulários são altamente interativos |

## Consequências

### Positivas
- Server Components por padrão → menos JS enviado ao cliente → melhor LCP
- SEO nativo (metadata API, robots.ts, sitemap.ts, JSON-LD)
- `output: 'standalone'` permite deploy em qualquer servidor Node.js
- Tailwind CSS v4 integrado nativamente

### Negativas
- Complexidade de decidir o que é Server vs Client Component
- Build mais pesado que SPA pura (SSR + bundle client)
- Breaking changes frequentes em versões recentes do Next.js
